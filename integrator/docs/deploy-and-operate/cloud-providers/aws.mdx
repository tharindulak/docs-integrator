# WSO2 Integrator on AWS

WSO2 Integrator has native support for Amazon Web Services ([AWS](https://aws.amazon.com/)). Connect to AWS services, add AI
with Amazon Bedrock, run your integrations on AWS, keep them secure
without storing access keys, and observe how they're running. This page covers
everything in one place, in the order you'll need it.

<ThemedImage light="../../../assets/img/aws/architecture-light.png" dark="../../../assets/img/aws/architecture-dark.png" alt="Architecture diagram: an event in AWS (SQS or Lambda) triggers WSO2 Integrator, which runs on ECS, EKS, EC2 or Lambda, optionally calls Amazon Bedrock for AI, and talks to AWS services like S3, DynamoDB, SNS, SES and Redshift -- secured by IAM roles and watched with CloudWatch, X-Ray and Prometheus." />

## [New to AWS?](https://docs.aws.amazon.com/)

### [Fargate](https://docs.aws.amazon.com/AmazonECS/latest/userguide/what-is-fargate.html)

A serverless compute engine for containers - no EC2 instances to manage, used by the recommended ECS deployment below.

### [IAM role](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)

An identity AWS gives your integration, so it can use AWS without access keys in your code.

### [Region](https://docs.aws.amazon.com/global-infrastructure/latest/regions/aws-regions-availability-zones.html)

The AWS location where your services run, for example <code>us-east-1</code>.

### [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-service.html)

The AWS service for using AI models from several providers through one API.

## Build for AWS {#build}

</div>

Decide how your integration interacts with AWS, add AI with Amazon Bedrock, and
use Bedrock for AI assisted development.

<div className="sub-steps">

<div className="sub-head">

### Connect with AWS

</div>

Most teams start with a connector.

#### Connect to AWS services

Add a connector from the palette and sign in with the IAM role of wherever it runs.

- [Browse AWS connectors](https://wso2.com/integration-platform/docs/connectors/catalog)

#### React to AWS events

Start an integration when a message lands in an SQS queue, or when an event invokes an AWS Lambda function.

- [SQS listener](../../guides/develop-and-test/integration-artifacts/event-driven-integration/aws-sqs.mdx)
- [Lambda event handlers](../deploy-and-run/self-hosted/serverless-deployment.mdx#aws-lambda)

#### Call any AWS API

No connector for a service? Call its API directly - request signing (SigV4), Region and FIPS endpoints are handled for you.

- [Call AWS APIs](../deploy-and-run/secure/aws-access.mdx#call-aws-apis-without-a-connector)

<div className="sub-head">

### Add AI with Amazon Bedrock {#ai}

</div>

Use AI models hosted on AWS, so your data stays in your AWS account.

#### Use Bedrock models

Call chat models and create embeddings through Amazon Bedrock, configured as a model or embedding provider.

- [Model providers](../../guides/develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/model-providers.mdx#aws-bedrock)
- [Embedding providers](../../guides/develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/embedding-providers.mdx#aws-bedrock)
- [Authentication](../../guides/develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/model-providers.mdx#aws-credential-options)

#### Answer from your own data (RAG)

Let AI answer from your documents using retrieval-augmented generation, with your source documents in S3.

- [Bedrock knowledge bases](../../guides/develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/knowledge-bases.mdx#aws-bedrock)
- [S3 Vectors](../../guides/develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/vector-stores.mdx#amazon-s3-vectors)
- [S3 data loader](../../guides/develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/data-loaders.mdx#aws-s3-text-data-loader)

#### Run agents on Bedrock AgentCore

Deploy AI agents to AgentCore and give them tools through AgentCore Gateway.

- [Deploy](../deploy-and-run/self-hosted/containerized-deployment.mdx#amazon-bedrock-agentcore-runtime-deployment)
- [Authentication](../deploy-and-run/secure/authentication.mdx#agents-on-amazon-bedrock-agentcore-runtime)
- [Tracing](../observe/tracing.mdx#on-amazon-bedrock-agentcore-runtime)

#### Give agents a memory

Store conversation memory in DynamoDB so agents remember earlier messages.

- [DynamoDB](../../guides/develop-and-test/integration-artifacts/ai-integrations/agents/memory.mdx#creating-an-amazon-dynamodb-short-term-memory-store)

## Deploy to AWS {#deploy}

</div>


Choose where your integration runs. Not sure? Start with ECS on Fargate.

### [Amazon ECS on Fargate <span class="badge badge--success">Recommended</span>](../deploy-and-run/self-hosted/containerized-deployment.mdx#amazon-ecs-deployment)

Run containers without managing any servers - the easiest place to start.

### [Amazon EKS](../deploy-and-run/self-hosted/containerized-deployment.mdx#amazon-eks-deployment)

Choose this if your team already runs Kubernetes.

### [Amazon EC2](../deploy-and-run/self-hosted/vm-deployment.mdx#run-on-amazon-ec2)

Choose this if you want a virtual machine you fully control.

### [AWS Lambda](../deploy-and-run/self-hosted/serverless-deployment.mdx#aws-lambda)

Choose this for short, event-driven jobs that run only when needed.

## Secure on AWS {#secure}

</div>


Follow these three practices from day one.

### Use IAM roles, not keys

Your integration picks up the role of wherever it runs - nothing secret lives in code.

- [Default credential chain](../deploy-and-run/secure/aws-access.mdx#use-the-default-credential-chain)
- [Attach an IAM role](../deploy-and-run/secure/aws-access.mdx#attach-an-iam-role)
- [Cross-account access](../deploy-and-run/secure/aws-access.mdx#access-resources-in-another-aws-account)

### [Keep secrets out of code](../deploy-and-run/secure/secrets-encryption.mdx#aws-secrets-manager)

Load passwords and settings from AWS Secrets Manager or SSM Parameter Store.

### [Keep traffic private](../deploy-and-run/secure/aws-access.mdx#keep-aws-traffic-inside-your-vpc)

Reach AWS services through VPC endpoints, with FIPS and dual-stack options.

## Observe in AWS {#observe}

</div>

### Logs

Collect logs in Amazon CloudWatch Logs.

- [CloudWatch Logs](../observe/logging.mdx#send-logs-to-amazon-cloudwatch-logs)

DEFAULT_CREDENTIALS` on a connector so it uses the IAM role of wherever it
runs. See [Access AWS services securely](../deploy-and-run/secure/aws-access.mdx).
