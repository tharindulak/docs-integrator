WSO2 Cloud is a fully managed platform that builds and runs your integrations from a Git repository. There are three ways to get your integrations onto WSO2 Cloud, depending on where your work lives.

These steps are the same whether your organization runs on the WSO2 Cloud data plane or a [private data plane](../deploy-on-private-data-plane/overview.mdx). The data plane determines where your integrations run, not how you deploy them.

## Deploy

- **[Deploy from the editor](./deploy-from-editor.mdx)** — Push a single integration or a whole project from the WSO2 Integrator editor.
- **[Deploy from the cloud editor](./deploy-from-cloud-editor.mdx)** — Build and deploy directly in the browser-based cloud editor, without installing anything locally.

You can also [import a project](../../../guides/develop-and-test/create-workspace/import-a-project.mdx) or [import an integration](../../../guides/develop-and-test/create-workspace/import-an-integration.mdx) from an existing repository. Importing connects it to a Git repository. From then on, every commit to the configured branch builds and deploys automatically, with no manual upload step. GitHub connects with one click; for Bitbucket, GitLab, or Azure DevOps, see [Connect a Git provider](./connect-git-provider.mdx) first.

## Once you're deployed

- **[Runtime configurations](../../manage/configurations/runtime-configurations.mdx)** — Set the configurable values an integration reads, per environment, and store sensitive ones as secrets.
- **[Troubleshoot deployment](./troubleshoot-deployment.mdx)** — Diagnose issues that only appear once an integration is running on WSO2 Cloud.
